# GitCurrent 发布签名与打包

## 当前工程配置

- Bundle ID：`com.fun2ex.Current`
- Developer Team：`7QSPARVZYS`
- 发布证书：`Developer ID Application`
- Hardened Runtime：Release 已启用
- 导出配置：`Config/ExportOptions-DeveloperID.plist`
- 产物：`GitCurrent.app`、arm64 Release ZIP、DMG、SHA-256 校验文件

当前发布格式是 ZIP 或 DMG 内的 `.app`，因此 `Developer ID Application` 即可；只有
改为签名 `.pkg` 安装器时，才需要另外申请 `Developer ID Installer` 证书。

## 单脚本发布

先在“钥匙串访问”中确认 Developer ID Application 证书和对应私钥都存在于登录钥匙串，
确认 GitHub CLI 已登录，然后在干净的 `main` 分支运行：

```bash
Scripts/release-macos.sh test
# 或
Scripts/release-macos.sh prod
```

脚本会自动读取远程标签并计算下一个版本：`test` 递增 `vX.Y.Z-test.N`，`prod` 使用
尚未发布的 `vX.Y.Z` 或递增稳定版本的 patch。随后它会递增 Xcode build number、生成
发布说明、构建并校验内置 Git、完成 Developer ID 签名、生成 ZIP/DMG、公证两个安装包、
提交版本变更、推送 `main` 和版本标签，最后创建 GitHub Release。

为了避免当前 Xcode/macOS 对 Swift Package 资源 bundle 重复签名时的时间戳冲突，archive
阶段显式保持无签名，随后由 `-exportArchive` 阶段完成一次 Developer ID 签名。钥匙串里
若存在多张同名证书，脚本会解析为当前 Team 下的具体证书指纹，也可以通过
`CODE_SIGN_IDENTITY=<SHA-1>` 明确指定某一张。

只查看下一版本而不修改仓库：

```bash
Scripts/release-macos.sh test --dry-run
```

要实际构建并验证下一版本，但不提交、推送或创建 Release：

```bash
Scripts/release-macos.sh test --validate-only
```

如果开发者账号刚开通，还需要先完成一次证书准备：

1. 在“钥匙串访问”中通过“证书助理 → 从证书颁发机构请求证书”生成 CSR，并保留生成的私钥。
2. 在 Apple Developer Certificates 中创建 `Developer ID Application` 证书，上传 CSR，下载 `.cer` 并双击安装。
3. 在钥匙串中确认该证书左侧能展开出同名私钥，再将证书和私钥一起导出为受密码保护的 `.p12`。

`.cer` 只有公钥证书，不能单独完成签名；`.p12` 必须同时包含证书和私钥。私钥文件、`.p12`
密码和 API Key 不要提交到仓库，也不要粘贴到对话中。

## 公证

Developer ID 签名不等于公证。正式对外分发还需要 App Store Connect API Key（`.p8`）、
Key ID 和 Issuer ID。建议将它们保存为本机 `notarytool` profile：

```bash
xcrun notarytool store-credentials current-notary \
  --key /path/to/AuthKey_<KEY_ID>.p8 \
  --key-id <KEY_ID> \
  --issuer <ISSUER_ID>
```

单脚本默认使用 `NOTARYTOOL_PROFILE=current-notary`，公证成功后会 staple、validate，
并将 ZIP、DMG 和各自的 SHA-256 文件附加到 GitHub Release。测试时如确实需要跳过
公证，可使用 `--no-notarize`；正式 `prod` 模式会拒绝该选项。

## 未来 CI 发布（可选）

当前发布由本机脚本负责，不需要把证书或 API Key 放入 GitHub。若未来要让 CI 调用同一
脚本，再补充以下 Secret：

- `MACOS_DEVELOPER_ID_CERTIFICATE_P12_BASE64`
- `MACOS_DEVELOPER_ID_CERTIFICATE_PASSWORD`
- `MACOS_SIGNING_KEYCHAIN_PASSWORD`
- `APP_STORE_CONNECT_API_KEY_P8_BASE64`
- `APP_STORE_CONNECT_API_KEY_ID`
- `APP_STORE_CONNECT_API_ISSUER_ID`

`.p12` 必须包含证书和私钥；只上传 `.cer` 没有签名能力。API Key 只用于公证，不能替代
Developer ID 证书。Sparkle 自动更新还另外需要 EdDSA 私钥、公钥、appcast URL，这些不
包含在本次 Apple 代码签名流程中。

当前 Release 发布由本机的 `Scripts/release-macos.sh` 负责；`.github/workflows/ci.yml`
仅负责测试和低版本 macOS 兼容性验证。若未来需要 CI 发布，可让 CI 直接调用同一脚本，
不再复制一套版本和打包逻辑。
