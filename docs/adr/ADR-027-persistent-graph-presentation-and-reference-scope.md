# ADR-027：持久化提交图呈现与引用范围

## 状态

Accepted

## 背景

大型仓库的提交图同时包含本地分支、远程分支和标签。不同任务需要不同的信息密度：审阅时
关注作者与日期，排障时关注 SHA，聚焦单一工作流时只希望看到一个引用可达的历史。列设置、
行密度和引用范围如果不能恢复，会让高频操作反复产生配置成本。

## 决策

- GraphKit 提供与仓库无关的 `GraphDisplayConfiguration`，描述可选列和行密度；AppModel
  负责用版本化的 UserDefaults key 持久化用户选择。
- Commit、Graph 两列始终可见；Author、Date、SHA 可独立隐藏。`NSTableView` 原生的
  `autosaveTableColumns` 保存列宽和列顺序。
- 行密度同时控制表格行高与图谱车道间距，保持节点、连线和文本的视觉比例。
- Solo 与 Hidden 引用使用已加载提交的父关系计算可达集合。过滤只影响图谱呈现，不修改
  仓库引用，也不清除当前 Changes/Diff 上下文。
- Pin 引用为每个已固定引用按名称分配稳定车道，并让其第一父链沿该车道延伸；固定车道在
  普通车道分配前保留，WIP 和未固定分支不会抢占。用户也可从 Graph Options 直接选择引用
  并滚动、选中其目标提交。
- 所有引用选择都按引用名称持久化。引用被删除后保留的名称不会影响图谱；再次出现时设置
  自动恢复。

## 后果

- 高频图谱布局设置可跨启动恢复，列宽和顺序仍由 AppKit 的原生表格机制管理。
- Solo/Hidden 的准确范围受当前已加载历史限制；加载更多历史后可达集合会自然扩展。
- 多个固定引用共享祖先时，先按引用名称排序的车道继续承载公共第一父链，其他车道通过真实
  父边汇入；固定只约束车道选择，不改变提交顺序或父子关系。

## 验证

- 单元测试覆盖单引用与多引用的可达提交过滤，以及 WIP、合流和多个固定引用的车道保留。
- Swift 测试套件、arm64 Debug 构建、设置窗口和 Graph Options 原生菜单作为合入门槛。
