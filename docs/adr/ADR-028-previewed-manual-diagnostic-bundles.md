# ADR-028：先预览后手动导出的诊断包

## 状态

Accepted

## 背景

D06-A 明确要求 Current 不接入第三方崩溃上传，也不自动上传仓库数据。用户仍需要一种可控的
方式向支持人员提供版本、运行环境和操作性能线索，并在发送前知道包内的准确内容。

## 决策

- 不启用后台诊断采集、遥测或自动上传；Settings 的 Privacy 区域明确显示两者均为 Off。
- 导出前展示 `manifest.json` 与 `operations.json` 的完整文本。包内不包含仓库路径或名称、
  refs、remote URL、文件名或内容、diff、环境变量、凭据或原始错误详情。
- 操作记录只保留规范化类别、状态、开始/结束时间和持续时间。动态分支、标签、remote、OID
  和路径不进入包；未知操作统一归类为 `Git operation`。
- token、Authorization、URL userinfo/query/path、用户主目录、SSH remote 与私钥块仍经过
  独立脱敏器，作为所有未来诊断文本字段的纵深防御。
- 系统报告默认不包含。用户可明确选择最多 5 个、每个不超过 20 MB 的普通文件，并在导出前
  用系统默认应用检查；报告内容按原样复制，但归档内改用 `system-report-N.ext` 中性名称，
  不记录原始路径或文件名。
- 使用结构化 `Process` 参数调用系统 `/usr/bin/ditto` 生成 ZIP，不经过 shell。临时目录和
  文件权限分别为 `0700` 与 `0600`，完成后删除。

## 后果

- SEC-05/WP-056 具备本地、可审阅、用户主动触发的诊断工作流，同时保持 D06-A 的无上传
  边界。
- 为降低泄漏风险，诊断包不能直接提供完整 Git stderr；支持人员需要根据操作类别、状态、
  版本与性能摘要指导用户复现。
- 用户选中的系统报告可能自身包含个人信息，因此 UI 明示其按原样复制，并提供逐个打开检查
  与移除入口。

## 验证

- secret fixture 覆盖凭据、Bearer token、URL、用户目录、SSH remote 和私钥块。
- 集成测试实际创建并解压 ZIP，验证准确文件集合、中性系统报告名称和原始文件名不泄漏。
- Swift 全量测试、arm64 Debug 构建与 Settings 原生窗口验收作为合入门槛。
